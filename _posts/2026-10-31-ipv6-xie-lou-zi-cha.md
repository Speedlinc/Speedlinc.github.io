一位做跨境协作的读者问过这样的问题：客户端明明显示已连接，查 IP 的网页上显示的也是节点地址，可有个网站打开时总是慢半拍，偶尔还会跳出“当前网络环境异常”的提示。后来一步步排查，问题出在一个很容易被忽略的地方——IPv6。

## IPv6 泄漏是什么？

IPv6 泄漏指的是：设备同时拥有 IPv4 和 IPv6 两种网络地址，加速只接管了 IPv4 的流量，而 IPv6 的请求仍然走本地网络直接发出去。结果是同一台设备、同一时刻，部分流量走节点，部分流量走本地线路。

这件事之所以会发生，是因为现代浏览器和系统遇到“双栈”网站时，会优先尝试 IPv6（常被称为 Happy Eyeballs 机制，目的是让访问更快）。如果加速软件的通道只覆盖 IPv4，而本地网络恰好又分配了 IPv6 地址，这部分请求就绕开了加速通道。

它带来的现象通常有三类：

- 同一个网站，有时快有时慢，因为两条线路交替被使用
- 查询出口 IP 时，IPv4 和 IPv6 显示的位置不一致
- 部分服务检测到“来源地址前后不一致”，要求额外验证

## 哪些情况更容易出现

| 情况 | 说明 | 风险程度（示意） |
|------|------|------|
| 家庭宽带已开启 IPv6 | 运营商下发了 IPv6 地址，系统默认启用 | 较高 |
| 手机使用移动网络 | 移动网络通常优先分配 IPv6 | 较高 |
| 公司或学校网络 | 多数仍以 IPv4 为主 | 较低 |
| 客户端本身只处理 IPv4 | 通道未覆盖 IPv6 请求 | 取决于客户端实现 |

上表中的风险程度是根据原理给出的示意判断，不是实测统计，具体情况取决于你的网络和客户端。

## 开了加速后怎么自查

自查的思路很简单：分别看 IPv4 和 IPv6 的出口是不是同一条线路。

### 第一步：确认设备有没有 IPv6 地址

macOS 或 Linux 可以在终端里运行 `ifconfig` 或 `ip -6 addr`，Windows 运行 `ipconfig`，看网卡信息中有没有以 `2` 或 `3` 开头的全局 IPv6 地址（以 `fe80` 开头的是本地链路地址，不算）。如果没有全局 IPv6 地址，基本不会发生泄漏，可以直接跳到总结。

### 第二步：分别查询 IPv4 与 IPv6 的出口

连上加速之后，在终端里分别执行：

```
curl -4 ifconfig.me
curl -6 ifconfig.me
```

第一条返回 IPv4 出口，第二条返回 IPv6 出口。如果第二条返回了一串地址，而且它归属的网络和节点不一致（可以用常见的 IP 归属查询工具对照），就说明 IPv6 请求没有走加速通道。如果第二条直接报错或超时，通常说明当前根本没有可用的 IPv6 出口，这属于正常情况。

### 第三步：对 IPv6 做针对性处理

发现不一致时，常见的处理方向有两个：

1. 先看客户端本身有没有处理 IPv6 的相关选项，并以官方说明为准
2. 临时在系统网卡层面关闭 IPv6：Windows 可以在网卡属性里取消勾选 IPv6，也可以用 PowerShell 的 `Disable-NetAdapterBinding -Name "Wi-Fi" -ComponentID ms_tcpip6`；macOS 可以用 `networksetup -setv6off Wi-Fi`，想恢复时用 `networksetup -setv6automatic Wi-Fi`

关闭后重新跑一遍第二步，再确认两条命令的结果是否都符合预期。注意网卡名称因设备而异，可以先用 `networksetup -listallnetworkservices` 查看。

### 第四步：打开断线保护作为兜底

IPv6 问题往往是“间歇出现”的，所以建议同时开启 Kill Switch。它的作用和机制可以看这篇：[Kill Switch 是什么？为什么断线保护这么重要](/zh/2026/10/04/kill-switch-shi-shen-me-duan-xian-bao-hu/)。出口 IP 到底是什么、怎么判断它是否变化，也可以顺着这篇继续了解：[出口 IP 是什么？怎么查看](/zh/2026/10/13/chu-kou-ip-shi-shen-me-zen-me-cha/)。

## 自查之后，还要留意什么

自查不是一次性的。系统更新、切换 WiFi、换到手机热点之后，IPv6 的状态都可能变化，所以在换了网络环境后，建议顺手再跑一次那两条命令。

另外，是否存在 IPv6 泄漏，既取决于本地网络，也取决于客户端实现。使用 TonBo VPN 这类提供完整客户端的网络加速器时，可以优先在设备上完成上面的对照检查，再决定是否需要在系统层面做调整，而不是凭感觉判断。

## 总结

IPv6 泄漏本质上是“双栈环境下，只有一半流量走了加速通道”。自查只需要三件事：看设备有没有全局 IPv6 地址，分别查 IPv4 与 IPv6 出口，必要时临时关闭系统 IPv6 并再次验证。养成换网络后复查的习惯，访问体验会稳定很多。
