晚上开始下载一个大模型，想着睡一觉就好了。第二天早上发现，进度停在 90% 附近，终端里一行连接重置的报错，临时文件还躺在硬盘上，却不知道能不能接着下。

大模型文件动辄数 GB 甚至更大，下载时间一长，任何一次网络抖动都可能让它中断。这篇不讲玄学，只讲两件事：怎么让下载具备"续传"的能力，以及怎么让线路在下载期间更稳定。

## 为什么大模型下载特别容易断

- **文件体积大**：下载持续时间长，遇到一次网络波动的概率自然高。
- **连接是长连接**：单个大文件通常需要一条连接持续传输很久，中途一旦被重置，没有续传机制就得从头开始。
- **线路波动不一定表现为"断网"**：丢包升高时，速度会先掉下来，再逐渐超时失败，表现为"下载慢，然后断"。

所以排查方向有两个：让下载工具能续，让线路少断。

## 先把断点续传用起来

下面的做法都是常见且通用的标准工具，具体参数和版本差异请以 Hugging Face 官方文档为准。

### 用官方命令行工具

先安装或更新官方的 Python 库：

```bash
pip install -U huggingface_hub
```

然后用命令行下载整个仓库，或指定其中的文件：

```bash
huggingface-cli download <仓库名> --local-dir ./my-model
```

官方工具在下载时会保留未完成的文件，重新执行同一条命令即可接着下，不需要手动清理。如果想提高下载速度，官方还提供了基于 Rust 的加速选项，需要额外安装并设置环境变量，详细用法见官方文档。

### 直接下载单个文件

文件有明确下载地址时，可以使用支持续传的下载工具：

```bash
# curl：-C - 表示自动续传
curl -L -C - -o model.safetensors <文件下载地址>

# wget：-c 表示续传
wget -c <文件下载地址>
```

续传的前提是服务端支持范围请求，主流的文件分发服务一般都支持，但仍建议先小文件试一次。

### 用 git 克隆仓库

如果使用 git 克隆，大文件由 Git LFS 管理。可以先只拉取代码和索引，再单独拉取大文件：

```bash
GIT_LFS_SKIP_SMUDGE=1 git clone <仓库地址>
cd <仓库目录>
git lfs pull
```

`git lfs pull` 中断后重新执行，会补齐缺失的文件。

## 下载完成后，一定要校验

下载中断、续传之后，文件有可能不完整。官方页面通常会提供每个文件的校验值，对照一遍更稳妥：

```bash
# macOS / Linux
shasum -a 256 model.safetensors

# Windows
certutil -hashfile model.safetensors SHA256
```

校验值不一致，就删除对应文件重新下载，不要直接拿去加载，否则可能出现莫名其妙的报错。

## 线路层面怎么让下载更稳

续传解决的是"断了怎么办"，线路稳定解决的是"少断几次"。

| 现象 | 可能原因（通常情况） | 处理方向 |
|------|------|------|
| 速度忽快忽慢，然后超时 | 线路抖动、丢包 | 换节点、避开拥堵时段 |
| 一直卡在连接阶段 | DNS 解析或路径异常 | 清 DNS 缓存，换出口 |
| 浏览器能开，终端下载失败 | 终端没有走加速通道 | 检查终端的代理环境变量 |

最后一行是个高发坑：浏览器走了系统层面的网络设置，命令行工具却不一定继承。这个排查思路在[Claude Code 长任务中断](/zh/2026/10/18/claude-code-ming-ling-xing-chang-ren-wu-zhong-duan/)里有更详细的说明，对 pip、git、下载命令同样适用。

## 常见问题

### 下载到一半断了，临时文件需要删除吗？

通常不需要。官方工具和 curl、wget 的续传功能都依赖已下载的部分，直接重新执行原命令即可。只有在校验值不一致时，才需要删除重下。

## 小结

大模型下载中断，首先要用好断点续传：官方命令行、curl、wget、git lfs 各有对应的续传方式；其次要做哈希校验，确保文件完整；最后在线路上多一层保障，避免抖动反复打断下载。把这三步做好，睡前开一个下载任务，早上就更有可能看到完成的提示。
